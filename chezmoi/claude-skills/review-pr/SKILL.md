# review-pr スキル

pull request の内容を確認しレビューします。

hunk のライブセッションが立ち上がっている場合 (`pr-review` シェル関数から起動されたときは常にそう) は、
レビューコメントをチャットに書き出すのではなく、hunk セッションのインラインコメント (Agent Note) として投稿する。

## 0. hunk セッションの検出

最初に `hunk session list --json` を実行し、`cwd` または `repoRoot` が現在の作業ディレクトリと一致するセッションを探す。

- ちょうど 1 件 → その `sessionId` を控えて **hunk モード**で進む
- 複数件 → `launchedAt` が最も新しいものを選ぶ。`pr-review` を同じ PR に対して撃ち直すと
  同じ `cwd` / 同じ `title` のセッションが増えていくので、`title` では区別できない。
  最後に起動されたものが、いま自分が動いているペインと一緒に立ち上がったセッションになる。
  `launchedAt` が無い / 同着で決められない場合だけユーザーに確認する
- 0 件 → hunk の daemon への登録が間に合っていない可能性がある。数秒あけて 5 回ほど引き直す
- それでも 0 件、またはコマンド自体が失敗 → **チャットモード**で進む (従来どおりレビュー結果をチャットに提示する)。
  このときは「hunk セッションが見つからないのでチャットに出力する」旨を必ずユーザーに伝える。黙って劣化しない

以降、hunk のコマンドにはこの `sessionId` を必ず明示的に渡す。`--repo .` は使わない。
同じリポジトリに複数のセッションがぶら下がっていると `Multiple active sessions match` で失敗するため。

## 1. hunk CLI の使い方を読み込む

hunk モードのときのみ。

```bash
hunk skill path
```

が出力するパスの SKILL.md を Read で開き、そこに書かれているコマンド仕様に従う。

**このスキルには hunk のコマンド構文を書かない。** hunk のバージョンによってフラグやペイロードの形が変わるので、
使い方は毎回インストール済みの実物から読む。

## 2. 実行フロー

1. レビュー対象の diff を取得する方法を確認
   - 呼び出し元のプロンプトで revset が指定されている場合 (`pr-review` 経由) はそれを使い、ユーザーに聞き直さない
   - 指定がなければユーザーに確認する。例: `jj diff --from main --to feature-branch`
2. PR Description (=diff の目的) をユーザーに確認
   - 例: `gh pr view {pr_number}` 等。直接入力でも可
3. 変更内容を分析
   - hunk モードでは、まず hunk のセッション情報からファイル/hunk 構造を取得する。
     そこに出てくるファイルパスが hunk の認識している綴りなので、コメントの宛先はそれに合わせる
     (`jj diff` の出力と食い違うことがある)
   - diff だけでは判断できない箇所 (呼び出し元、関連する既存実装、テストの有無) は実ファイルを開いて確認する
   - 変更の種類を特定 (feat, fix, refactor など)
4. レビューコメントを生成
   - PR Description の内容との一致、コードの品質、可読性、パフォーマンス、セキュリティなどの観点
   - 些末な指摘を乱発しない。ユーザーが自力で気づきにくい点に絞る
5. 出力
   - **hunk モード**: 生成したコメントを Agent Note として投稿する (複数あるならバッチ投入を 1 回で行う)。
     投稿後、チャットには件数と全体の所感だけを短く書く。個々の指摘をチャットに再掲しない
   - **チャットモード**: 生成したレビューコメントをチャットに提示する

## コメントを打つときの決まり

- 位置は行番号 (new 側 / old 側) で指定するのを基本にする。
  hunk 番号はセッション情報の JSON が 0 始まりで返すのに対しコマンドの引数は 1 始まりなので、取り違えやすい
- 追加・変更された行への指摘は new 側、削除された行への指摘は old 側。どちらか一方だけを指定する
- `--author` にはレビュアーだと分かるラベルを付ける
- **`hunk session reload` は使わない。** 表示中の diff は `pr-review` が意図した revset を `--watch` で開いているものなので、
  差し替えるとユーザーが読んでいる画面を壊す
- **`hunk session comment clear` は使わない。** 不要になったコメントは個別に削除する

## 注意事項

- サンドボックス制限がある場合は `dangerouslyDisableSandbox: true` を使用
- jj st, jj show, jj log は並列で実行可能
